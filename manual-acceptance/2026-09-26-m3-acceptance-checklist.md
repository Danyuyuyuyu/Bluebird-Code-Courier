## A. 访问令牌（故事 1–2、23）

- [ ] A1. 未配置令牌首次启动直接进设置页
  操作：① 退出应用；② 删除（或改名备份）应用数据目录 `%APPDATA%\OCTO 仓库监控器`；③ 项目根目录运行 `npm start`。
  验收：窗口打开后直接显示设置页（含令牌输入框），无需任何点击。

- [ ] A2. 输入错误令牌报错并留在设置页
  操作：① 设置页令牌输入框输入无效值（如 `ghp_wrong`）；② 点"保存"。
  验收：出现令牌无效错误条，页面停留在设置页。

- [ ] A3. 输入正确令牌成功提示并跳转监控清单
  操作：① 输入有效 GitHub PAT；② 点"保存"。
  验收：提示"访问令牌已保存并验证通过"，约 1 秒后自动跳转到监控清单页。

- [ ] A4. 重启后不用重新输令牌
  操作：① 关闭应用窗口；② 重新 `npm start`。
  验收：直接进入应用（不被设置页拦截），功能照常。

## B. 监控清单（故事 3–7）

- [ ] B1. 添加 owner/repo 立即显示三条轻量信息
  操作：① 监控清单页输入框输入真实仓库（如 `facebook/react`）；② 点"加入清单"。
  验收：清单新增一行，显示 star 数、最近动态时间、最新发版标签三条信息。

- [ ] B2. 粘贴 GitHub 网址归一入列；非 github.com 明确报错
  操作：① 输入 `https://github.com/microsoft/TypeScript/tree/main/README.md`（浏览器复制的深层路径）点"加入清单"；② 输入 `https://gitee.com/foo/bar` 点"加入清单"。
  验收：① 入列且显示 `microsoft/TypeScript`；② 报"仅支持 github.com 的仓库地址"，清单不变。

- [ ] B3. 添加不存在/无权限的仓库报错且不留条目
  操作：① 输入不存在的仓库（如 `foo/this-repo-does-not-exist-xyz`）；② 点"加入清单"。
  验收：立即报错（不存在/无权限），清单里不留任何条目。

- [ ] B4. 非法输入明确提示格式
  操作：① 输入 `foo`；② 点"加入清单"。
  验收：明确提示格式（含 owner/repo 与网址两种形态说明），清单不变。

- [ ] B5. 重复添加报错且不重复（含大小写不同）
  操作：① 对清单已有仓库再输入同一 `owner/repo` 点"加入清单"；② 再输入仅大小写不同的同一网址（如 `https://github.com/Facebook/React`）点"加入清单"。
  验收：两次都报"该仓库已在监控清单中"，清单条数不变。

- [ ] B6. 删除两步确认后消失
  操作：① 点某行的"删除"；② 4 秒内按钮变为"确认删除？"再点一次。
  验收：该行从清单消失；只点一次不删（4 秒后按钮复原为"删除"）。

- [ ] B7. 重启清单还在（M3：清单持久化）
  操作：① 添加至少一个仓库后关闭窗口；② 重新 `npm start`。
  验收：清单仍在，轻量信息照常显示。

## C. 抓取与错误降级（故事 8–9、21–23）

- [ ] C1. 启动自动抓取一次；"重新抓取"手动刷新
  操作：① 启动应用进清单页，观察行内"抓取于 …"；② 点"重新抓取"。
  验收：启动自动抓取一次（"抓取于 …"为相对时间）；点按钮后显示"抓取中…"（按钮禁用 + 转圈），完成后时间更新。

- [ ] C2. 断网刷新旧数据仍在 + 网络失败错误条
  操作：① 断开网络（关 Wi-Fi/拔网线）；② 点"重新抓取"；③ 恢复网络再点"重新抓取"。
  验收：断网时旧数据照常显示、出现网络失败错误条、不白屏不崩溃；恢复后抓取恢复正常。

- [ ] C3. 令牌失效报"去设置"，换令牌后继续用
  操作：① GitHub 网页 Settings → Developer settings → Personal access tokens 撤销当前令牌；② 回应用点"重新抓取"；③ 点错误条"去设置"，在设置页保存新令牌；④ 回清单点"重新抓取"。
  验收：步骤②出现令牌无效错误条 + "去设置"按钮；步骤④恢复正常抓取。

- [ ] C4. 限流提示带恢复时间
  操作：无需人工造场景（正常配额难以触发，已由测试覆盖）。
  验收：免人工验收；若偶发限流，错误条应带配额恢复时间。

## D. 全量信息（故事 10–17、20）

- [ ] D1. 点行进详情自动抓取，五个更新类别分区
  操作：① 在清单点击任一仓库行。
  验收：进入全量信息页并自动抓取，分区显示：发版 / 提交 / 议题与合并请求 / 构建状态 / 星标趋势。

- [ ] D2. 发版字段齐全；无发版仓库显示空态
  操作：① 打开有 release 的仓库详情看发版分区；② 打开没有 release 的仓库详情。
  验收：① 每条显示标签 / 标题 / 日期；② 显示"无发版"空态。

- [ ] D3. 提交字段齐全
  操作：① 详情页看提交分区。
  验收：每条显示消息 / 作者 / 时间。

- [ ] D4. 议题与合并请求分开两列
  操作：① 详情页看议题与合并请求分区（找一个两类都有的仓库）。
  验收：议题与合并请求分开两列，每条有 #编号、标题、状态徽章、作者、时间。

- [ ] D5. 构建状态徽章
  操作：① 打开有 GitHub Actions 的仓库详情；② 打开没有工作流的仓库详情。
  验收：① 显示 构建通过 / 失败 / 构建中 之一；② 显示"无构建"。

- [ ] D6. 星标趋势随使用积累
  操作：① 快照 ≤1 条时（新装机当天）看趋势分区；② 隔天再用一天后回来看。
  验收：① 显示"趋势随使用积累"提示；② 出现 star / fork 双折线。

- [ ] D7. 详情"重新抓取"生效；失败保留上次内容
  操作：① 详情页点"重新抓取"；② 断网后再点"重新抓取"。
  验收：① 数据刷新；② 保留上次内容并显示错误条。

## E. 历史快照（故事 18–19，M3：快照当日不重复）

- [ ] E1. 同一天多次刷新每仓库每天只一档
  操作：① 同一天多次点"重新抓取"；② 执行 `SELECT repository_id, day, COUNT(*) FROM snapshot GROUP BY 1,2 HAVING COUNT(*)>1`；③ 隔天再用一天后重查。
  验收：② 查询结果为空；③ 隔天每天各一档。

## F. 窗口与本机数据（故事 24–27）

- [ ] F1. 普通窗口（无托盘），关闭即退出
  操作：① 观察窗口与系统托盘；② 关闭窗口；③ 任务管理器查 `electron.exe`。
  验收：无托盘图标；关闭后进程退出，无残留 electron.exe。

- [ ] F2. 飞行模式下本机数据可翻，抓取失败不崩溃
  操作：① 开飞行模式；② 启动应用翻清单与趋势；③ 打开某仓库详情。
  验收：清单与趋势照常（本机数据）；详情抓取失败只报错不崩溃。

- [ ] F3. 小窗仍可用
  操作：① 把窗口缩到约 480px 宽。
  验收：布局不破、主要操作可用（小屏友好）。

## G. 冷启动与打包（M3）

- [ ] G1. 冷启动就绪 ≤8 秒
  操作：① 清单放 5 个仓库；② 关闭应用重新启动并计时。
  验收：≤8 秒内轻量信息就绪（行内出现抓取数据）。

- [ ] G2. NSIS 安装包干净机器独立运行
  操作：① 运行 `npm run dist`；② 在干净机器运行 `release/` 下 NSIS 安装包，安装并启动。
  验收：安装后正常运行，数据独立（各用各的令牌和清单）。
