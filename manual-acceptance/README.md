# manual-acceptance

人工验收清单目录：UI 行为按 spec 只做人工验收，自动化测试覆盖不到的验收项在此登记、勾选、留痕。

## 文件命名

- 清单：`〈YYYY-MM-DD〉-〈milestone〉-acceptance-checklist.md`
  - 时间戳取**清单创建日**的 ISO 日期，做前缀（便于按时间排序）；里程碑小写；同里程碑多轮验收各建一份。
  - 目录与文件一律 kebab-case 英文。
- 模板：`_template.md`（元文件，不带日期）。

## 创建一份新清单

1. 复制 `_template.md` 为 `〈YYYY-MM-DD〉-〈milestone〉-acceptance-checklist.md`。
2. 标题写明来源：spec 路径、用户故事范围、里程碑验收项。
3. 分组名沿用 CONTEXT.md 的领域词汇，故事编号放组头（如 `## A. 访问令牌（故事 1–2、23）`）；复合场景拆成原子条目。
4. 填"验收信息"表：版本/构建、执行人/日期、环境与前提、状态。

## 条目写法

    - [ ] A1. 〈验收点一句话〉
      操作：① 〈前置准备与每一步，可照做〉；② 〈…〉。
      验收：〈可观察的预期现象〉。

- **完整操作过程**：到达验收点的每一步都写出（含前置准备、按钮名、命令）。
- **只验收需要验证的部分**：勾选只针对"验收"判据；操作步骤本身不打勾、不验收。
- 命令核对项给出可粘贴命令与预期结果；自动化测试已覆盖的项注明"（已由测试覆盖，无需人工造场景）"并免于人工验收。

## 验收时

- 通过打 `[x]`；失败留 `[ ]` 并在条目后追加 `❌ 现象：…`，或登记"遗留问题"表；无法执行标 `N/A` 注明原因。
- 条目编号（`A1` 式）用于遗留问题引用。
- 验完填"结论"：通过 / 有条件通过 / 不通过 + 一句话备注。
